# 005：版本化本地 JSON 备份

## 问题

用户需要周期自动备份、立即备份以及可选择路径的 JSON 导入和导出。运行时 Snapshot 同时含有可恢复的用户状态和不应持久保存的 Provider 数据。

## 选择

使用带固定格式标识和整数版本号的专用 BackupDocument。只复制 settings、widgets、content；通过 Rust 后端写入和读取。标准备份保存到应用数据目录，导入/导出路径使用 Windows 原生文件对话框。导入复用正式模型校验与 SQLite 事务，成功后才替换运行状态。

## 原因

- 明确字段比直接导出运行时 Snapshot 更容易保证不包含 Codex 数据。
- 版本号让后续模型迁移能拒绝不支持的新格式或显式转换旧格式。
- 后端拥有 SQLite 和完整模型，可在一个信任边界内完成大小限制、校验与保存。
- Windows 原生文件对话框无需引入新的网络依赖，并允许用户选择标准 JSON 文件路径。

## 替代方案

- 复制 SQLite：不利于人工查看、版本迁移和选择性排除运行数据。
- 前端 Blob 下载和文件输入：Tauri WebView 的下载路径行为不够统一，且会把完整导入校验拆到两个边界。
- 新增对话框插件：能减少 Win32 代码，但当前环境无需为一个 Windows 专用功能下载依赖。

## 影响

备份恢复包含 Memo/Todo/Countdown，因为它们是本地用户状态。导入会替换现有配置、组件布局和这些内容，因此 UI 必须在打开导入操作前明确提示。Provider 缓存保持当前运行值，不从备份恢复。自动备份文件会限量保留，用户单独导出的文件不受清理影响。
