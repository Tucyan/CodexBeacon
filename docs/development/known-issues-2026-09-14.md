## VALIDATION-025 透明窗口黑色矩形

- 用户证据：圆角卡片之外的窗口矩形区域变黑，卡片透明背景也变暗。
- 用户补充（2026-09-14）：电脑卡顿十几秒无响应，文件资源管理器随后自动重启，之后出现截图中的黑底；偶发，不影响日常体验。希望改善，但不是必须解决项。优先级低、非发布阻断，不要求用户专门复现系统卡死。
- 已确认实现：`window/mod.rs` 已设置 transparent(true)、shadow(false)，CSS 根背景透明。因此不能仅通过再次关闭阴影解释或解决。
- 待验证假设：系统卡顿及 Explorer 重启后透明合成未恢复；Explorer 重启是已报告触发过程，不证明 Explorer、DWM 或 WebView2 中哪一层是根因。不再将 UU 视为本问题的已知触发条件；本机/远程画面对照仍未确认。
- 实验方法：后续在可控实验环境对照 Explorer 重启前后状态及正常退出重启应用的效果；采集 Windows/WebView2 版本、Shell 重建和渲染恢复记录。不得为复现主动制造系统卡死，也不在未告知用户时重启正在使用的 Explorer。
- 候选实现：先修复背景透明初始化/恢复；若证实渲染表面失效，显示状态稳定后有限重建受影响 WebView 窗口，恢复布局及已提交内容，避免循环刷新或丢失未保存编辑。只在证据支持时采用。
- 人工通过标准：本机与 UU 下透明角落无黑底，编辑内容保留，无持续闪烁。

## VALIDATION-026 屏幕配置与布局

- 代码证据：当前只有一份组件几何数据；`native::work_area` 读取主屏工作区；`lifecycle::window_event` 将 Moved/Resized 保存为布局，没有显示切换事务。系统调整坐标可能覆盖原布局。未完成实际切屏重现。
- 采用方向：按显示配置保存布局。仅分辨率不足，配置键应包含显示器标识、分辨率、DPI 缩放、排列；工作区同时记录用于位置映射。虚拟远程屏需稳定的回退匹配策略。
- 实现方式：显示切换期间暂停几何回写，待配置稳定后加载已有配置；首次配置继承上一份已保存布局，按工作区比例映射并将整个组件限制到可见范围。切回恢复原配置；任务栏工作区变化不无限新建配置。区分用户移动与系统调整。
- 已实现：在现有SQLite通用settings表保存活动拓扑键及布局配置，无需改表；旧数据库启动时将当前布局登记为首个配置。JSON备份v2包含全部布局，仍兼容导入不含布局配置的v1备份。
- 验证：不同分辨率、相同分辨率不同缩放、远程虚拟屏、来回切换、重启及旧 JSON 导入。明确扩展原首版“不做多屏特殊适配”的范围，以用户本轮需求为依据。
- 临时措施：先导出 JSON 并锁定布局；锁定可阻止当前事件处理器写回，但不能代替配置恢复。

## VALIDATION-027 UU 远程刷新后遮挡普通应用

- 已确认实现：显示桌面探针依据 Explorer 桌面与 sentinel 的 Z 顺序；判定 Active 后 E 策略临时 HWND_TOPMOST。没有独立的远程/显示变化重建探针流程。
- 待验证假设：UU 或显示变化改变窗口顺序，产生显示桌面误判或未退出临时置顶。尚无故障时 Z 顺序快照，不能断言唯一原因。
- 实验方式：记录显示变化、探针状态转换、前台窗口、置顶标志及具体 SetWindowPos 原因；对照自动出现/跟随系统、UU 连接与刷新、Win+D/任务栏显示桌面。
- 候选实现：显示/会话变化立即撤销临时置顶，重建探针基线；状态未知时保持非置顶；加入普通应用前台状态的交叉验证与有限恢复。保留用户输入焦点，不周期性抢前台。窗口事件回调避免重入。
- 人工标准：普通应用始终可覆盖组件，组件仍可输入，自动出现功能不回归。
- 临时措施：Behavior → Show desktop behavior → 跟随系统；会暂时放弃“显示桌面时自动出现”。
