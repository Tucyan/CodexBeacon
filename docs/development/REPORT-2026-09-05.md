## 实现方式与分工

| 模块 | 实现方式 | 责任 |
|---|---|---|
| 独立窗口 | 每内置组件独立 Tauri WebviewWindow；无共同 Canvas；隐藏创建，前端监听/快照/DOM 就绪后才显示；组件禁用销毁窗口，关闭转 Hide | 主 agent |
| 显示桌面 | 自有隐藏 sentinel + 只读桌面宿主层级观察；E 策略临时置顶，离开桌面时降级；Unknown 不强制置顶；Hide/禁用优先 | 主 agent |
| 渐显 | prepare/token → 前端同步准备透明度 → appearance_ready → 原生显示 → 250ms CSS ease-out；2秒准备超时降级；设置可关闭 | 主 agent + frontend_app |
| 状态与权限 | Rust 权威 Snapshot/Action；revision 排序；Settings 全量，组件仅自身数据/所需 Provider；后端核对布局锁与调用来源 | 主 agent |
| 保存/退出 | 编辑串行进入 Rust；数据库400ms防抖；隐藏/禁用/退出前 flush 握手；最终冻结修改并事务保存，失败取消退出；自 Hide 在前端队列之前排空保存 | 主 agent + frontend_app |
| SQLite | Windows 自带 winsqlite3 C API；预编译参数绑定、事务、WAL、外键、user_version migration；分表保存设置、实例、memo/todo/countdown；不存凭据或 Provider 原始响应 | sqlite_store |
| 前端 | React/TypeScript strict、Registry、独立路由、Memo/Todo/Countdown、设置/主题/倍率、失败保存重试 | frontend_app |
| Codex | 一个自有长期 app-server 子进程，stdio JSON-RPC，限时请求、异常关闭及退避；额度60秒、usage300秒；可选usage方法缺失降级；只白名单字段出 Provider | rust_providers |
| Reset | WinHTTP调用已验证公开API；长期client保留ETag/304缓存、15分钟更新、Retry-After门控；无Codex凭据传入 | rust_providers |

三个 subagent 完成独立模块后交叉审查。已修正内容保存失败后误确认、appearance监听/DOM时序、HEX中间态覆盖、方向字符串不一致、SQLite NUL绑定、额外content键、退出保存竞争等具体问题。
